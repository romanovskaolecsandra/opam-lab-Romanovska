## Теоретичні відповіді на запитання

### 1. Чому порядок у першому способі вилучення дублікатів (Завдання 3) змінився?
Колекція `HashSet<T>` побудована на основі хеш-таблиці. Вона оптимізована для швидкої перевірки унікальності, але не зберігає порядок додавання елементів. Внутрішній порядок елементів залежить від їхніх хеш-кодів та розподілу по внутрішніх бакетах (Buckets).

### 2. Чому виграш словників/множин зростає разом із розміром даних?
Пошук у звичайному `List<T>` виконується за лінійний час \(O(n)\) — комп'ютер змушений перебирати кожен елемент по черзі. Що більше елементів у списку, то довше працює цикл. 
У `HashSet<T>` та `Dictionary<K, V>` пошук працює за сталий час \(O(1)\) завдяки хешуванню (комп'ютер миттєво обчислює адресу елемента у пам'яті). Тому при збільшенні обсягу даних час списку зростає стрімко, а словника чи множини — залишається майже незмінним.

### 3. За якого розміру даних різниця стає непомітною і чи варто тоді брати словник?
На малих обсягах даних (приблизно до 20–30 елементів) різниця у швидкодії становить мікросекунди і є невідчутною. Проте навіть для малих обсягів словник варто використовувати, якщо він логічно підходить під структуру задачі (зв'язок "Ключ-Значення") — це робить код чистішим для читання.

### 4. Що словник віддає в обмін на швидкість?
1. **Оперативну пам'яті (Memory Overhead):** Для забезпечення швидкості \(O(1)\) словники зберігають додаткові внутрішні таблиці бакетів та індексів зв'язків, що вимагає значно більше пам'яті, ніж компактний список.
2. **Порядок елементів:** Звичайний словник чи множина не гарантують збереження первинного порядку елементів при обході колекції.
