# Лабораторна робота 5

Параметри: N = 22, K = 19, a = 1, b = 2, c = 2

## Результати тестів

### Завдання 1 (Дужки)
* "(a[b]{c})" -> збалансований, індекс: -1
* "([)]" -> незбалансований, індекс: 2
* ")(" -> незбалансований, індекс: 0
* "((" -> neзбалансований, індекс: 2
* "" -> збалансований, індекс: -1

Спеціальний тест варіанта (19 відкривальних і 18 закривальних):
* Вхідний рядок: ((((((((((((((((((())))))))))))))))))
* Результат: незбалансований
* Індекс першої помилки: 37 (кінець рядка, бо стек залишився непустим)

### Завдання 2 (ОПЗ)
* "3 4 + 2 *" -> 14
* "5 3 -" -> 2
* "8 2 /" -> 4
* "2 3 4 * +" -> 14
* "5 0 /" -> Повідомлення про помилку: ділення на нуль

Власний вираз для результату 19 (використано 3 операції):
* "5 4 * 2 / 9 +" -> Результат: 19

## Вимірювання місткості стеку (Завдання 4)

Початковий розмір масиву був заданий як 5. На 6-му Push масив автоматично розширився вдвічі:
* Push 1: Count = 1, Capacity = 5
* Push 2: Count = 2, Capacity = 5
* Push 3: Count = 3, Capacity = 5
* Push 4: Count = 4, Capacity = 5
* Push 5: Count = 5, Capacity = 5
* Push 6: Count = 6, Capacity = 10

## Обґрунтування вибору структур даних (Завдання 5)

1. Для дужок потрібен саме стек, бо ми маємо перевіряти їх у порядку "останній відкрився — перший закрився" (LIFO). Якщо взяти чергу, то перша закривальна дужка порівнюватиметься з найпершою відкривальною, що повністю зламає логіку вкладених виразів.

2. Для ОПЗ стек зручний тим, що будь-яка математична операція виконується над двома останніми числами, які ми щойно прочитали. Список тут не потрібен, бо нам не потрібен доступ до елементів всередині, а лише до верхніх двох.

3. Для обслуговування заявок потрібна саме черга (FIFO), щоб перші клієнти обслуговувалися першими. Якщо взяти стек, то остання заявка піде на обробку першою, а найперші заявки зависнуть назавжди.

Властивість Queue.Dequeue() працює за константний час O(1), оскільки елементи просто беруться з голови черги (зсувається вказівник). Метод List.RemoveAt(0) працює за лінійний час O(N), бо після видалення першого елемента всі інші елементи в пам'яті доводиться фізично зсувати вліво на одну позицію. Це сильно гальмує роботу програми, якщо елементів багато.
